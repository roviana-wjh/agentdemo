## Phase 1: 单Agent链式协作（2-3天）

### 目标
实现5个Agent顺序协作完成文章创作

### 架构图
```
用户输入
    ↓
研究员Agent (搜索知识)
    ↓
架构师Agent (设计大纲)
    ↓
作家Agent (撰写文章)
    ↓
审核Agent (质量检查)
    ↓
编辑Agent (润色优化)
    ↓
输出成品
```

### 文件结构
```
flow/
├── collaborative_writing/
│   ├── graph.go              # 主Graph定义
│   ├── state.go              # State结构定义
│   ├── agents/

│   │   ├── architect.go      # 架构师Agent
│   │   ├── writer.go         # 作家Agent
│   │   ├── reviewer.go       # 审核Agent
│   │   └── editor.go         # 编辑Agent
│   └── types.go              # 共享类型
└── collaborative_writing_test.go

api/
└── collaborative_writing.go  # HTTP接口
```

## Phase 2: 反馈循环（1-2天）

### 目标
审核不通过时自动重写，最多3次迭代

### 架构变化
```
作家Agent → 审核Agent
               ↓
          [条件分支]
         /           \
   不通过(≤3次)    通过
        ↓            ↓
   重写(返回作家)   编辑Agent
```

### Day 4-5: 迭代机制
- [ ] 添加ReviewIteration计数
- [ ] 实现条件分支逻辑
- [ ] 审核反馈注入到State
- [ ] 作家Agent使用反馈改进
- [ ] 测试迭代流程

### 验收标准
- ✅ 审核失败时自动重写
- ✅ 最多重写3次后强制通过
- ✅ 每次重写质量提升
- ✅ 记录完整的迭代历史

## Phase 3: 角色分工并行（2天）

### 目标
不同角色Agent并行生成文章不同部分

### 架构
```
架构师Agent
    ↓
[并行生成]
├─ 正文作家Agent
├─ 代码工程师Agent
├─ 配图设计Agent
└─ 案例专家Agent
    ↓
组装Agent (合并所有内容)
    ↓
审核 → 编辑
```
